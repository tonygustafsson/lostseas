# Townsfolk and quests implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add 48 talkable NPCs (tavern, market, governor in each town) with 1640-era dialogue, questions with answers, and generated quests shown in the Status drawer.

**Architecture:** Fixed NPC and dialogue data in `constants/`. Pure server actions in `utils/actions/npc.ts` pick lines, resolve placeholders, roll and progress quests, with per-visit state in `locationStates.conversations`. All dialogue text lives in `constants/dialogue/`, which is server-only, so it never ships to the browser. The client gets the light NPC roster plus the single line returned by each talk. Thin API routes and a `useNpc` hook feed a `TalkDialog` opened from `NpcCard`s in Tavern, Market and City hall.

**Tech stack:** Next.js App Router, TypeScript, React Compiler, TanStack Query, zustand, shadcn `components/ui`, framer-motion, Vitest, Storybook.

**Spec:** `docs/superpowers/specs/2026-11-06-quests-design.md`

## Global constraints

- Never commit, stage, stash or push. Every task ends with lint and format on touched files instead of a commit.
- Format: `npx prettier --write <files>`. Lint: `npm run lint`. Tests: `npx vitest run <file>`.
- Actions are pure, return `ActionResult`, take `randomInt: RandomInt = getRandomInt` last. Test with `createTestPlayer` and `createSeededRandom`.
- No `if (x) return`. Always use braces.
- No `useMemo`/`useCallback`. Avoid `useEffect` except for the typewriter timer.
- Theme tokens only. One gold button per view. Secondary buttons use `variant="secondary"`.
- UK English in all player-facing text. No em dashes in dialogue.
- 3 talks per NPC per visit. Quest roll 1 in 10. Question roll 1 in 2. Max 5 active quests.
- Dialogue set in 1640: no references to later events. The game's towns and nations are the truth.
- Dialogue has humour: roughly a third of lines and replies should be funny (dry wit, absurd sailor logic, petty grudges, comic exaggeration, self-deprecation), in each personality's own voice. Not slapstick, not every line, and answers that invite a joke often get a funny reply. Tone reference: classic point-and-click pirate adventure comedy. Most questions offer at least one cheeky or absurd answer for the player (a deadpan non sequitur, a sarcastic jab, a ridiculous boast), and NPCs react to it in character. Write only original jokes, never lines, names, insults or running gags from existing games.
- Placeholders (dialogue): `{name}`, `{title}`, `{town}`, `{nation}`, `{enemy}`, `{playerNation}`, `{otherTown}`, `{nationTown}`, `{enemyTown}`, `{merchandise}`, `{month}`, `{year}`.
- Firebase drops empty arrays, so arrays in stored state are optional.
- New UI gets Storybook stories covering every prop and state.
- Dialogue never reaches the client. Every file in `constants/dialogue/` starts with `import "server-only"` (already used in `firebase/db.ts`). Only actions and routes import them, never components, hooks, `constants/npcs.ts`, `questBusiness.ts` or `questText.ts`. Tests that import dialogue add `vi.mock("server-only", () => ({}))`, like `__tests__/passkey.test.ts`.

## Review focus

1. Procurement giver: talking to them without enough goods must give normal chatter, not a stuck reminder. Test in Task 7.
2. Find a person: talking again in an already ruled out town must give normal chatter, not repeat "not here". Test in Task 7.
3. Placeholder resolution must leave no `{...}` in any returned text, including replies and quest pitches. Test in Tasks 1 and 6.
4. Arriving in a new town must reset talks. `startJourney` sets `locationStates: null`. Test in Task 5.
5. Answering with no pending question, or an out-of-range index, must return an error, not crash. Test in Task 5.
